## 2. Сравнительный анализ технологий

### 2.1. Матрица принятия решений

Для выбора СУБД были определены 5 критериев, специфичных для финансовых транзакций и баллов. Сумма весов строго равна 1.0.

| Критерий | Что это значит (простыми словами) | Вес | PostgreSQL (1–5) | MongoDB (1–5) |
|---|---|---|---|---|
| **Поддержка ACID** | Деньги и баллы не потеряются и не задвоятся при сбое. | 0.35 | 5 | 3 |
| **Гибкость схемы** | Легко ли менять структуру данных без сложных миграций. | 0.15 | 3 | 5 |
| **Скорость чтения** | Как быстро достаются история транзакций, баллы и промокоды. | 0.20 | 4 | 4 |
| **Стоимость владения** | Хостинг, специалисты, время на поддержку. | 0.15 | 4 | 3 |
| **Экосистема** | Готовые библиотеки, миграции, бэкапы, мониторинг. | 0.15 | 5 | 4 |
| **Сумма весов** | | **1.00** | | |

### 2.2. Расчет и обоснование выбора

Взвешенная оценка рассчитывается по формуле:  
**`Оценка = Σ (Вес_критерия × Балл_кандидата)`**

- **PostgreSQL:** `0.35×5 + 0.15×3 + 0.20×4 + 0.15×4 + 0.15×5 = 1.75 + 0.45 + 0.80 + 0.60 + 0.75 = 4.35`
- **MongoDB:** `0.35×3 + 0.15×5 + 0.20×4 + 0.15×3 + 0.15×4 = 1.05 + 0.75 + 0.80 + 0.45 + 0.60 = 3.65`

**Вывод:** победителем выбрана **PostgreSQL (4.35 против 3.65)**. Для системы лояльности и финансовых транзакций критически важна строгая поддержка ACID и целостность данных, где реляционная СУБД дает максимальные гарантии. MongoDB выигрывает только в гибкости схемы, что для данной задачи вторично.
